Overview

frontend/BottomBar.qml is the persistent control surface that appears at all times. It is a Rectangle with a themed gradient background, containing three logical sections arranged via a Loader that switches between horizontal and vertical layout components.

Layout and Structure

The BottomBar is a Rectangle with a gradient background that adapts direction based on orientation:

Rectangle {
    id: bottomBar
    gradient: Gradient {
        orientation: isVertical ? Gradient.Horizontal : Gradient.Vertical
        GradientStop { position: 1.5; color: App.Style.bottomBarGradientStart }
        GradientStop { position: 0.0; color: App.Style.bottomBarGradientEnd }
    }

    required property StackView stackView
    required property Window mainWindow
}

A Loader at the top level switches between two complete layout components:

Loader {
    anchors.fill: parent
    sourceComponent: isVertical
        ? verticalLayoutComponent : horizontalLayoutComponent
}

The horizontal layout uses a RowLayout with three sections. The vertical layout uses a ColumnLayout. Both contain the same controls, just arranged differently.

Section 1: Media Controls (Horizontal Mode)

Takes 40% of width when visible, or 10% when hidden (for symmetry). Visibility is controlled by settingsManager.showBottomBarMediaControls.

Section 2: Navigation (Center)

Uses Layout.fillWidth: true to fill remaining space, with navigation buttons centered via a RowLayout.

Dual Orientation

The isVertical property controls whether the bar appears at the bottom (horizontal) or left side (vertical) of the window:

property bool isVertical: settingsManager &&
    settingsManager.bottomBarOrientation === "side"

The updateLayout() function reconfigures anchors when orientation changes:

function updateLayout() {
    if (isVertical) {
        anchors.bottom = undefined
        anchors.right = undefined
        anchors.left = parent.left
        anchors.top = parent.top
        width = parent.width * 0.1
        height = parent.height
    } else {
        anchors.top = undefined
        anchors.right = undefined
        anchors.left = parent.left
        anchors.bottom = parent.bottom
        width = parent.width
        height = parent.height * App.Spacing.bottomBarHeightPercent
    }
}
Anchor Release Pattern: Anchors are released (set to undefined) before new ones are assigned. This prevents binding loops that occur when conflicting anchor constraints are temporarily active.

Parent size changes are also tracked via Connections to ensure correct sizing after window resizes.

Media Transport Controls

Each media button follows a consistent pattern using Control with an SVG image and ColorOverlay:

Control {
    id: previousButtonControl
    implicitWidth: App.Spacing.bottomBarPreviousButtonWidth
    implicitHeight: App.Spacing.bottomBarPreviousButtonHeight

    // Press animation
    scale: mouseAreaPrev.pressed ? 0.8 : 1.0
    opacity: mouseAreaPrev.pressed ? 0.7 : 1.0

    Behavior on scale {
        NumberAnimation {
            duration: 200
            easing.type: Easing.OutBack
            easing.overshoot: 1.1
        }
    }

    contentItem: Item {
        Image {
            id: previousButtonImage
            source: "./assets/previous_button.svg"
            visible: false  // Hidden; used as ColorOverlay source
        }
        ColorOverlay {
            source: previousButtonImage
            color: App.Style.bottomBarPreviousButton
        }
    }
}

Enlarged Hit Areas

Every button wraps its MouseArea in an invisible Item that is significantly larger than the visual icon (typically 2.5x width, 3x height). This improves touch accuracy on car touchscreens:

Item {
    id: previousButtonClickArea
    anchors.centerIn: parent
    width: parent.width * 2.5
    height: parent.height * 3.0

    MouseArea {
        id: mouseAreaPrev
        anchors.fill: parent
        onClicked: useSpotify
            ? spotifyManager.previous_track()
            : mediaManager.previous_track()
    }
}

Play/Pause Button

The play/pause button dynamically switches its icon based on playback state:

source: {
    var isPlaying = useSpotify ?
        (spotifyManager && spotifyManager.is_playing()) :
        (mediaManager && mediaManager.is_playing())
    return isPlaying
        ? "./assets/pause_button.svg"
        : "./assets/play_button.svg"
}

Volume Slider and Mute

Volume Display

The volume percentage is shown as a small text label. Clicking it opens a full-width popup with a large slider:

Popup {
    id: popupSlider
    width: parent.Window.width
    height: App.Spacing.dp(140)
    anchors.centerIn: Overlay.overlay
    modal: true
    closePolicy: Popup.CloseOnEscape | Popup.CloseOnPressOutside
}

Logarithmic Volume Curve

The slider range is 0-100 (linear). The actual audio volume is computed with a squared curve for perceptually even loudness:

onValueChanged: {
    volumeControl.currentValue = value
    var normalizedValue = value / 100
    var logVolume = Math.pow(normalizedValue, 2.0)

    // Sync to all audio outputs
    settingsManager.setCurrentVolume(Math.round(value))
    mediaManager.setVolume(logVolume)

    if (spotifyManager && spotifyManager.is_connected())
        spotifyManager.set_volume(Math.round(value))

    if (phoneMirrorManager)
        phoneMirrorManager.setVolume(logVolume)
}
Volume Sync: Volume changes from the slider are applied to four outputs simultaneously: local media (QMediaPlayer), Spotify API, Phone Mirror (scrcpy), and the settings store (for persistence and ESP32 LED feedback).

Touch-Friendly Slider

The popup slider includes 9 circular touch areas evenly distributed along the track. Each one maps touch position back to the slider value, making it much easier to hit on a car touchscreen:

Repeater {
    model: 9
    MouseArea {
        width: App.Spacing.dp(80)
        height: App.Spacing.dp(80)
        onMouseXChanged: {
            if (pressed) {
                var globalX = mapToItem(volumeSlider, mouseX, mouseY).x
                var newPosition = Math.max(0, Math.min(1,
                    (globalX - volumeSlider.leftPadding)
                    / volumeSlider.availableWidth))
                volumeSlider.value = newPosition * 100
            }
        }
    }
}

Mute Button

The mute button toggles mute state via mediaManager.toggle_mute(). Special case: if volume is 0, clicking mute restores to the startup volume instead:

onClicked: {
    if (volumeControl.currentValue === 0 && settingsManager) {
        var startupVol = Math.round(settingsManager.startUpVolume * 100)
        volumeSlider.value = startupVol
    } else {
        mediaManager.toggle_mute()
    }
}

The mute icon dynamically changes between volume levels (high, medium, low, muted) based on the current volume value.

Shuffle State

Shuffle is a shared state property on the BottomBar, acting as the single source of truth:

property bool isShuffleEnabled: false

Component.onCompleted: {
    if (useSpotify && spotifyManager)
        isShuffleEnabled = spotifyManager.is_shuffled()
    else if (mediaManager)
        isShuffleEnabled = mediaManager.is_shuffled()
}

The shuffle button's background changes to bottomBarToggleShade when active, and its icon color shifts to bottomBarActiveToggleButton (the accent color).

Manager Communication

The BottomBar communicates with backend managers through the useSpotify flag:

property bool useSpotify: settingsManager &&
    settingsManager.mediaSource === "spotify" &&
    spotifyManager && spotifyManager.is_connected()

Every media action checks this flag and dispatches to the correct manager:

  • useSpotify ? spotifyManager.previous_track() : mediaManager.previous_track()
  • useSpotify ? spotifyManager.toggle_play() : mediaManager.toggle_play()
  • useSpotify ? spotifyManager.next_track() : mediaManager.next_track()
  • useSpotify ? spotifyManager.toggle_shuffle() : mediaManager.toggle_shuffle()

Connections to settingsManager track orientation changes and trigger updateLayout().

External Volume Sources

Volume changes can arrive from multiple external sources beyond the UI slider:

SourceManagerHow It Works
ESP32 Volume Knobesp32VolumeManagerWireless rotary encoder sends volume deltas over serial. The BottomBar syncs its slider to match.
Gesture SensorgestureManagerPAJ7620U2 sensor detects swipe gestures for volume up/down
Settings startupsettingsManagerUnified currentVolume restored from settings on app launch

All sources converge on the same logarithmic curve: logVolume = (value/100)^2.0. The squared curve makes perceived volume changes feel linear to the human ear.

Button Animation Pattern

Every interactive button in the BottomBar follows a consistent animation pattern using Qt Quick Behavior declarations:

// Press: scale down with spring effect
scale: mouseArea.pressed ? 0.8 : 1.0
Behavior on scale {
    NumberAnimation {
        duration: 200
        easing.type: Easing.OutBack
        easing.overshoot: 1.1
    }
}

// Press: reduce opacity
opacity: mouseArea.pressed ? 0.7 : 1.0
Behavior on opacity {
    NumberAnimation { duration: 150 }
}

The Easing.OutBack with overshoot creates a subtle "bounce" when the button returns to its normal size, giving satisfying tactile feedback on touchscreens.

SVG Icon Pattern

All icons follow a pattern where the Image is hidden and used only as a source for ColorOverlay. This allows theme colors to tint the icons dynamically:

Image {
    id: iconImage
    source: "./assets/icon.svg"
    sourceSize: Qt.size(width * 2, height * 2)
    fillMode: Image.PreserveAspectFit
    smooth: true
    antialiasing: true
    mipmap: true
    visible: false  // Hidden
}

ColorOverlay {
    anchors.fill: iconImage
    source: iconImage
    color: App.Style.bottomBarHomeButton  // Theme color
}
2x sourceSize: SVGs are rasterized at 2x the display size for crisp rendering on high-DPI displays. The mipmap: true flag ensures clean downscaling.
