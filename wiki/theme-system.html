Style.qml — Color Themes

frontend/Style.qml is the central color theme store. It defines built-in themes, supports custom themes loaded from settings, and provides the Album Art Capture feature.

Theme Resolution

The activeTheme property drives all color bindings. It resolves in priority order:

property var activeTheme: {
    // 1. Album Art Capture (dynamic, real-time)
    if (currentTheme === "Album Art Capture" && albumArtTheme)
        return albumArtTheme

    // 2. Custom themes (loaded from settings)
    if (customThemes[currentTheme])
        return customThemes[currentTheme]

    // 3. Built-in themes
    return themes[currentTheme] || themes["SolarizedLight"]
}

Custom Themes

Users can create custom themes that are stored in settingsConfigure.json. They are loaded at startup in Main.qml:

let customThemes = settingsManager.customThemes
customThemes.forEach(function(themeName) {
    let themeJSON = settingsManager.get_custom_theme(themeName)
    let themeObj = JSON.parse(themeJSON)
    App.Style.addCustomTheme(themeName, themeObj)
})

When custom themes change at runtime (via the customThemesChanged signal), the entire custom themes map is rebuilt atomically to avoid briefly clearing the active theme.

Album Art Capture

The "Album Art Capture" theme extracts dominant colors from the current song's album art and generates a full theme object dynamically. The pipeline:

  1. A new track starts playing in mediaManager or spotifyManager
  2. Python extracts dominant colors from the album art image
  3. A complete theme JSON is generated and emitted via albumColorsExtracted(themeJson) signal
  4. Main.qml receives the signal and calls Style.updateAlbumArtTheme(themeJson)
  5. Style.qml parses the JSON, stores it as albumArtTheme, forces activeTheme to re-evaluate by toggling currentTheme
  6. All color properties with Behavior on animations smoothly transition to the new palette

Color Transitions

Every color property in Style.qml has a Behavior on that creates smooth animated transitions:

property color backgroundColor: activeTheme.base
Behavior on backgroundColor {
    ColorAnimation { duration: colorTransitionMs }
}

The colorTransitionMs property defaults to 1000ms but can be dynamically set to match the current song's duration when songLengthTransition is enabled, creating an ambient color shift that spans the entire track.

EnvironmentTheme.qml — UI Shape Presets

frontend/EnvironmentTheme.qml controls the shape and visual effects of UI components, independent of color. It defines environment presets that change border radii, enable special effects like scanlines and corner brackets, and alter the visual personality of the UI.

pragma Singleton
QtObject {
    property string currentEnvironment: "Standard"
    signal environmentChanged()

    property var active: environments[currentEnvironment]
        || environments["Standard"]

    function setEnvironment(name) {
        if (environments[name]) {
            currentEnvironment = name
            environmentChanged()
        }
    }
}

Environment Presets

Three presets are defined, each controlling dozens of visual parameters:

Standard

Clean, modern defaults. Rounded corners (12px cards), solid buttons, no special effects.

Spacecraft

Military/HUD aesthetic with sharp corners (2px), corner brackets, animated dividers, glow borders, tick marks, uppercase labels, scanline overlays, and pulsing elements.

Deep Sea

Organic, fluid aesthetic with large radii (16px), glass effects, sonar ping animations, floating bubbles in the sidebar, and subtle accent borders.

Spacing.qml — Layout Scaling

frontend/Spacing.qml handles responsive layout. All sizes are derived from applicationWidth and applicationHeight through percentage-based calculations and scale factors.

Scale Factor Chain

property real globalScale: 1.0       // User preference multiplier
property real autoScaleFactor: 1.0  // Auto-detected from screen
property real effectiveScale: autoScaleFactor * globalScale
property real baseScale: 0.6 * globalScale

effectiveScale is used by dp() for hardcoded pixel values designed at 720p. baseScale is used by scaledSize() for percentage-based properties that already adapt to screen size.

Scaling Functions

dp(size) — Density-Independent Pixels

function dp(size) {
    return Math.round(size * effectiveScale)
}

Converts a reference pixel value (designed at 720p) to the actual screen resolution.

dpMin(size, floor) — With Minimum

function dpMin(size, floor) {
    return Math.max(floor, Math.round(size * effectiveScale))
}

Same as dp() but with a minimum value. Used for border radii that should never go sub-pixel.

scaledSize(baseSize) — Percentage Scaling

function scaledSize(baseSize) {
    return Math.round(baseSize * baseScale)
}

Applied to percentage-based properties. The input is already proportional to screen size, so only the design factor (0.6) and user preference are applied.

Key Calculated Properties

Spacing.qml computes dozens of pixel values from percentage properties. Examples:

// Bottom bar sizing
property int bottomBarHeight:
    scaledSize(applicationHeight * 0.125)

// Button sizes (from min dimension)
property int bottomBarPlayButtonWidth:
    scaledSize(Math.min(applicationWidth, applicationHeight) * 0.1275)

// Grid spacing
property int sectionSpacing:
    scaledSize(Math.min(applicationWidth, applicationHeight) * 0.05)

Customization Guide

Creating a New Built-in Theme

  1. Open frontend/Style.qml
  2. Add a new entry to the themes object following the existing structure
  3. Define all required keys: base, baseAlt, accent, text, states, sliders, bottombar, mediaroom, mainmenu, obd
  4. The theme will automatically appear in the theme picker

Adding a New Environment Preset

  1. Open frontend/EnvironmentTheme.qml
  2. Add a new entry to the environments object
  3. Define all shape/effect properties (copy from Standard as a base)
  4. The preset will appear in the environment picker via getAllEnvironmentNames()

Adding a New Font

  1. Drop a .ttf or .otf file into frontend/assets/fonts/
  2. Main.qml's FolderListModel will discover it automatically at next launch
  3. The font name (derived from filename) will appear in the font picker

Font System

Style.qml also manages the font system. The fontFamily property is the resolved font family name used by all UI components:

// Always returns a valid font family name
property string fontFamily: currentFont === "System Default"
    ? systemDefaultFont
    : (fontFamilyMap[currentFont] || systemDefaultFont)

Available fonts are populated at startup by Main.qml after scanning the frontend/assets/fonts/ directory. The availableFonts array always starts with "System Default":

function registerFonts(fontList, familyMap) {
    availableFonts = ["System Default"].concat(fontList)
    fontFamilyMap = familyMap
    fontsUpdated()
}

The fontFamilyMap maps display names (derived from filenames) to the actual font family names reported by Qt's FontLoader. This mapping is necessary because the filename may differ from the internal font family name.

How Components Consume the Theme

Components access theme values through the App.Style namespace. The reactive color properties ensure automatic updates when the theme changes:

// Direct color binding (auto-updates with transitions)
color: App.Style.backgroundColor
color: App.Style.primaryTextColor
color: App.Style.accent

// Environment-aware shape properties
radius: App.Spacing.dpMin(
    App.EnvironmentTheme.active.cardRadius, 2)

// Conditional features based on environment
visible: App.EnvironmentTheme.active.cornerBrackets
visible: App.EnvironmentTheme.active.sliderTickMarks

The pattern of using Behavior on { ColorAnimation { duration: colorTransitionMs } } on every color property means theme switches are always smooth, never jarring. This is especially important for Album Art Capture where colors change with every track.

Performance: Every Behavior on creates an active animation object. With 40+ color properties each having a behavior, theme transitions involve 40+ simultaneous ColorAnimation instances. This is manageable on desktop but can impact performance on Raspberry Pi. Consider reducing colorTransitionMs on low-powered devices.
