Overview

The DownloadManager provides music search and download functionality within OCTAVE. It combines Spotify metadata with YouTube audio sources to download high-quality music files. Defined in backend/download_manager.py, it wraps the internal music_dl engine (a fork of spotdl) and exposes search/download operations to QML via the standard OCTAVE manager pattern.

No Spotify Credentials Required
The search system uses YouTube Music (ytmusicapi) by default, so Spotify credentials are optional. When provided, they enable Spotify URL resolution (track, album, playlist URLs) for richer metadata.

The music_dl Engine

The music_dl package lives in backend/music_dl/ and is a forked and trimmed version of spotdl. It provides the core download pipeline independent of the Qt/QML layer.

Entry Point: MusicDL Class

The MusicDL class in backend/music_dl/__init__.py is the main API: 

class MusicDL:
    def __init__(self, client_id, client_secret, headless=False,
                 downloader_settings=None):
        self.has_spotify = bool(client_id and client_secret)
        if self.has_spotify:
            SpotifyClient.init(client_id=client_id, ...)
        self.downloader = Downloader(settings=downloader_settings)

    def search(self, query):     # -> List[Song]
    def download(self, song):    # -> Tuple[Song, Optional[Path]]
    def download_songs(self, songs):  # -> List[Tuple[Song, Optional[Path]]]

Search Flow

When the user types a query in the QML search bar and calls downloadManager.search(query), the following flow executes:

Text Queries (Default Path)

  1. Lazy-init engine -- _ensure_music_dl() creates the MusicDL instance if not already initialized, loading Spotify credentials from the settings manager keychain.
  2. YouTube Music search -- Calls ytmusicapi.search(query, filter="songs", limit=20) via the get_ytm_client() singleton from backend/music_dl/utils/search.py.
  3. Parse results -- Each YTMusic result is transformed into a standardized result dict containing: name, artist, artists, album_name, duration (seconds), year, cover_url, song_id (YouTube video ID), and a YouTube Music URL.
  4. Enhance cover art URLs -- Google CDN thumbnail URLs are rewritten to request 800x800 high-resolution versions: 
    if "lh3.googleusercontent.com" in cover_url:
    cover_url = re.sub(r"=w\d+-h\d+.*$", "=w800-h800-l90-rj", cover_url)
  5. Mark downloaded -- The _mark_downloaded() method scans the media library to tag results that already exist on disk (sets is_downloaded: true and downloaded_playlist name).
  6. Emit to QML -- Results are JSON-serialized and emitted via searchResults signal.

Spotify URL Queries

When the query contains open.spotify.com or spotify.link and Spotify credentials are available, the engine uses MusicDL.search([url]) which resolves the Spotify URL into Song objects with full metadata (including ISRC codes for better matching).

Pagination
The ytmusicapi does not support offset-based pagination. All results are returned in a single batch (up to 20). The search_more() slot simply emits "All results shown".

Download Pipeline

When the user clicks download on a search result, QML calls download_song(song_json) with the full song data serialized as JSON.

  1. Parse song data -- JSON is deserialized and a unique song_id (YouTube video ID) is extracted for deduplication.
  2. Duplicate guard -- Checks _pending_futures to prevent downloading the same song_id concurrently.
  3. Build Song object -- Depending on the source:
    • Spotify URL: Song.from_url(url) fetches full Spotify metadata
    • YouTube Music result: Song.from_missing_data(**song_data) with the YT Music URL set as download_url so yt-dlp uses it directly
  4. Download & convert -- MusicDL.download(song) delegates to the Downloader which:
    • Searches YouTube for matching audio (or uses the direct URL)
    • Downloads with yt-dlp
    • Converts to the target format via ffmpeg
    • Embeds metadata (ID3 tags, album art) via utils/metadata.py
    • Saves to the configured output path with sanitized filename
  5. Emit result -- On success, downloadComplete is emitted with the song_id and file path. The search result is patched with is_downloaded: true via downloadStatusChanged for in-place QML ListView updates.

URL Downloads (Albums/Playlists)

The download_from_url(url) slot handles Spotify album and playlist URLs. It resolves the URL into multiple Songs via MusicDL.search() and then batch-downloads them all with MusicDL.download_songs().

Output Filename Template

"{artists} - {title}.{output-ext}"
# Example: "Joji - Test Drive.mp3"

Progress Reporting

Download progress flows from the music_dl engine to QML through a thread-safe queue:

Worker Thread Main Thread | | | progress_handler callback | | _on_download_progress() | | | | | push to _progress_updates | | (under _progress_lock) | | | | QTimer (200ms poll) | _poll_futures() | | | drain _progress_updates | emit downloadProgress(song_id, 0.0-1.0) | | | QML ListView update

The callback receives a tracker object with a progress field (0-100) which is normalized to 0.0-1.0:

def _on_download_progress(self, tracker, message):
    song_id = tracker.song.song_id if tracker.song else ""
    progress = tracker.progress / 100.0
    with self._progress_lock:
        self._progress_updates.append((song_id, progress))

In-Place Status Patching

To avoid rebuilding the entire QML ListView on each status change, the manager emits targeted patches via downloadStatusChanged(song_id, field, value_json). QML can update individual list items by matching song_id.

Download Path & Playlist Targeting

Downloads are saved into a subfolder of the media library. The path is constructed as: 

# mediaFolder / subfolder / "Artist - Title.mp3"
download_path = os.path.join(media_folder, subfolder)

The subfolder can be:

  • The downloadSubfolder setting (default: "Downloads")
  • A runtime override set via set_download_playlist(name) -- this allows downloading directly into a specific playlist folder
Path Traversal Protection
The subfolder is validated using is_safe_path() from backend/media_manager.py to prevent directory traversal attacks. If the path escapes the media folder, it falls back to "Downloads".

Duplicate Detection

Search results are checked against existing files in the media library to prevent re-downloading. The matching uses the same filename sanitization as the download engine: 

@staticmethod
def _sanitize_for_match(text):
    # Mirror sanitize_string from music_dl/utils/formatter.py
    text = "".join(c for c in text if c not in "/?\\*|<>")
    text = text.replace('"', "'").replace(":", "-")
    return text.lower()

The method _get_downloaded_files() walks the entire media library, collecting audio filenames (mp3, flac, ogg, opus, m4a) mapped to their containing folder name. Each search result's expected filename ("Artist - Title") is matched against this index.
