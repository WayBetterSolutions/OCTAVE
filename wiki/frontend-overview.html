QML Architecture Overview

OCTAVE's frontend is built with Qt Quick 2.15 (QML) using PySide6. The QML layer handles all visual presentation, animations, and user interaction. Business logic lives in Python backend manager classes that are exposed to QML as context properties.

 ApplicationWindow (Main.qml)
 +-------------------------------------------+
 |  mainContainer (Item)                     |
 |  +---------------------------------------+|
 |  |  StackView (page navigation)          ||
 |  |  +-----------------------------------+||
 |  |  | MainMenu.qml (initialItem)        |||
 |  |  | MediaPlayer.qml                   |||
 |  |  | MediaRoom.qml                     |||
 |  |  | OBDMenu.qml                       |||
 |  |  | SettingsMenu.qml                  |||
 |  |  | ...                               |||
 |  |  +-----------------------------------+||
 |  +---------------------------------------+|
 |  |  BottomBar.qml (persistent nav+media) ||
 |  +---------------------------------------+|
 |  |  globalFullScreenFlash (z: 999999)    ||
 |  +---------------------------------------+|
 +-------------------------------------------+

Key architectural points:

  • Single window — one ApplicationWindow hosts everything
  • StackView navigation — pages are pushed/popped onto a stack; no router library
  • Persistent BottomBar — always visible below (or beside) the StackView
  • Singleton design tokens — Style.qml, Spacing.qml, and EnvironmentTheme.qml are pragma Singleton objects
  • No page transitions — all StackView enter/exit transitions are set to null for performance

Main.qml Structure

The entry point file frontend/Main.qml is an ApplicationWindow that orchestrates the entire UI. Here is its top-level declaration:

import QtQuick 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15
import Qt.labs.folderlistmodel 2.15
import "." as App

ApplicationWindow {
    id: mainWindow
    visible: true
    title: deviceName
    minimumWidth: 400
    minimumHeight: 300
    font.family: App.Style.fontFamily !== ""
        ? App.Style.fontFamily : systemDefaultFont
}

The window stores a captured systemDefaultFont at startup, before any custom fonts are applied. This ensures there is always a valid fallback.

Window Management

Window dimensions are persisted bidirectionally. On startup, Main.qml reads saved dimensions from settingsManager. On resize, it writes them back:

onWidthChanged: {
    if (settingsManager && width > 0 && width >= minimumWidth) {
        settingsManager.save_screen_width(width)
        screenWidth = width
        App.Spacing.updateDimensions(width, height)
    }
}

The Spacing.updateDimensions() call recalculates all percentage-based layout values. Window state (fullscreen, maximized, normal) is also saved and restored:

// Restore window state
let savedState = settingsManager.get_window_state()
if (savedState === "fullscreen")
    mainWindow.visibility = Window.FullScreen
else if (savedState === "maximized")
    mainWindow.visibility = Window.Maximized
Cleanup on Close: The onClosing handler saves playback state, clears temp files, and cleans up Spotify before the window closes.

Page Routing Mechanism

OCTAVE uses Qt's StackView for page navigation. The initial item is MainMenu:

StackView {
    id: stackView
    objectName: "stackView"

    initialItem: MainMenu {
        stackView: stackView
        windowWidth: mainWindow.width
        windowHeight: mainWindow.height
    }

    // Disable all transitions for performance
    pushEnter: null
    pushExit: null
    popEnter: null
    popExit: null
}

Pages push themselves onto the stack by creating components dynamically. For example, navigating to OBD from the BottomBar:

var component = Qt.createComponent("OBDMenu.qml")
var page = component.createObject(stackView, {
    stackView: bottomBar.stackView,
    mainWindow: stackView.parent.Window.window
})
stackView.push(page)

The navigateTo() function provides a complete page map for remote/programmatic navigation:

function navigateTo(pageName) {
    var pageMap = {
        "MainMenu.qml":    { file: "MainMenu.qml",    props: { ... } },
        "MediaRoom.qml":   { file: "MediaRoom.qml",   props: { ... } },
        "MediaPlayer.qml": { file: "MediaPlayer.qml", props: { ... } },
        "OBDMenu.qml":     { file: "OBDMenu.qml",     props: { ... } },
        // ... 12 pages total
    }
}

There are also navigateHome() (pops to root) and navigateBack() (pops one) helper functions, primarily used by a Python command server for performance testing.

StackView Anchoring

The StackView adapts its anchoring based on bottom bar orientation:

anchors {
    left: isVerticalLayout ? bottomBar.right : parent.left
    right: parent.right
    top: parent.top
    bottom: isVerticalLayout ? parent.bottom : bottomBar.top
}

When the bottom bar is vertical (side mode), the StackView fills from the bar's right edge to the window's right edge. When horizontal, it fills from the top to the bar's top edge.

Import Path Setup

The Python launcher adds frontend/ to the QML import path in main.py. This means any QML file in frontend/ can be imported by name without a path prefix. The import "." as App pattern used throughout the codebase creates a namespace alias:

import "." as App

// Access singletons via the App namespace
App.Style.backgroundColor
App.Spacing.dp(10)
App.EnvironmentTheme.active.cardRadius

Settings sub-components use import ".." as App since they are one directory deeper.

Accessing Python Managers (Context Properties)

Backend managers are registered as QML context properties in main.py. They appear as global variables in every QML file:

# In main.py (Python)
engine.rootContext().setContextProperty("mediaManager", media_manager)
engine.rootContext().setContextProperty("spotifyManager", spotify_manager)
engine.rootContext().setContextProperty("settingsManager", settings_manager)
engine.rootContext().setContextProperty("obdManager", obd_manager)

In QML, these are consumed directly:

// Call Python slots
mediaManager.next_track()
spotifyManager.toggle_play()
settingsManager.save_theme_setting(newTheme)

// Read Python properties
text: settingsManager.deviceName

// Connect to Python signals via Connections
Connections {
    target: mediaManager
    function onMetadataChanged(title, artist, album) { ... }
}

Dynamic Font Loading

Main.qml scans for custom fonts at startup using a FolderListModel:

FolderListModel {
    id: fontFolderModel
    folder: Qt.resolvedUrl("assets/fonts")
    nameFilters: ["*.ttf", "*.otf", "*.TTF", "*.OTF"]
}

For each font file found, a FontLoader is dynamically created. Once all fonts are loaded, they are registered with Style.registerFonts() which makes them available in the settings UI font picker. The saved font preference is then applied via Style.setFont().

Album Art Capture Pipeline

When the "Album Art Capture" theme is active, album art colors are extracted and applied to the entire UI in real time. Main.qml connects to multiple signal sources:

// From mediaManager (local media)
function onAlbumColorsExtracted(themeJson) {
    App.Style.updateAlbumArtTheme(themeJson)
}

// From spotifyManager (Spotify)
function onAlbumColorsExtracted(themeJson) {
    lastAppliedAlbumArtColors = themeJson
    App.Style.updateAlbumArtTheme(themeJson)
}

// Duration-based transition speed
function onDurationChanged(durationMs) {
    if (settingsManager.songLengthTransition && durationMs > 0)
        App.Style.colorTransitionMs = durationMs
}

The songLengthTransition feature makes color transitions match the song duration, creating a slow ambient color shift throughout playback.

Shift Light Logic

Main.qml implements a full-screen RPM shift light overlay for track/racing use. The system works as follows:

  1. Load flags — loadShiftLightFlags() reads RPM threshold definitions from settings as a JSON array. Each flag has rpmLow, rpmHigh, color, flash, flashSpeed, fullScreenFlash, and fullScreenFlashOpacity properties.
  2. Track RPM — obdManager.rpmChanged signal updates currentRpm.
  3. Find active flag — findActiveFlag() iterates flags from highest to lowest priority, selecting the first whose RPM range contains the current value.
  4. Flash overlay — A Rectangle at z-index 999999 covers the entire UI. It is visible only when the active flag has fullScreenFlash === true.
  5. Flash timer — A Timer toggles visibility at the flag's flashSpeed interval to create a flashing effect.
Rectangle {
    id: globalFullScreenFlash
    anchors.fill: parent
    z: 999999
    visible: mainWindow.shiftLightEnabled &&
             mainWindow.activeShiftFlag !== null &&
             mainWindow.activeShiftFlag.fullScreenFlash === true &&
             mainWindow.shiftLightFlashVisible
    color: mainWindow.activeShiftFlag
        ? mainWindow.activeShiftFlag.color : "transparent"
    enabled: false  // Allow clicks to pass through
}
Performance Note: The flash overlay is deliberately placed as the last child of mainContainer so it renders on top without requiring a separate window or popup, which ensures cross-platform compatibility.

Settings Manager Connections

Main.qml has an extensive Connections block that reacts to settings changes in real time. These handlers keep the UI synchronized with the backend state:

Theme and Appearance

function onThemeSettingChanged() {
    var newTheme = settingsManager.themeSetting
    App.Style.setTheme(newTheme)
    // If Album Art Capture, extract colors from current song
    if (newTheme === "Album Art Capture" && mediaManager) {
        var currentFile = mediaManager.get_current_file()
        if (currentFile)
            mediaManager.extract_colors_from_album_art(currentFile)
    }
}

function onEnvironmentThemeChanged() {
    App.EnvironmentTheme.setEnvironment(settingsManager.environmentTheme)
}

function onFontSettingChanged() {
    App.Style.setFont(settingsManager.fontSetting)
}

Song Length Transition

When song-length color transitions are disabled, the saved manual transition speed is restored:

function onSongLengthTransitionChanged() {
    if (!settingsManager.songLengthTransition) {
        App.Style.colorTransitionMs = settingsManager.colorTransitionMs
    }
}

Bottom Bar Orientation

When the bar switches between bottom and side mode, the entire settings page is reloaded after a 150ms delay to account for the layout change:

function onBottomBarOrientationChanged() {
    isVerticalLayout = settingsManager.bottomBarOrientation === "side"
    bottomBar.isVertical = isVerticalLayout

    // If on settings page, reload it after layout settles
    if (stackView.currentItem &&
        stackView.currentItem.objectName === "settingsMenu") {
        navReloadTimer.restart()
    }
}

Custom Theme Hot-Reload

Custom themes are rebuilt atomically to avoid a flash where the active theme temporarily disappears:

settingsManager.customThemesChanged.connect(function() {
    var newCustomThemes = {}
    let customThemes = settingsManager.customThemes
    customThemes.forEach(function(themeName) {
        let themeJSON = settingsManager.get_custom_theme(themeName)
        newCustomThemes[themeName] = JSON.parse(themeJSON)
    })
    // Assign in one shot to avoid briefly clearing active theme
    App.Style.customThemes = newCustomThemes
    App.Style.customThemesUpdated()
})

Drop Shadows

Main.qml renders drop shadows between the StackView and the BottomBar for visual depth. Two shadow rectangles exist — one for each orientation:

// Bottom shadow (horizontal mode)
Rectangle {
    id: bottomBarShadow
    visible: !isVerticalLayout
    anchors.bottom: bottomBar.top
    height: 12
    gradient: Gradient {
        GradientStop { position: 0.0; color: "transparent" }
        GradientStop { position: 1.0; color: "#30000000" }
    }
}

// Side shadow (vertical mode)
Rectangle {
    id: sideBarShadow
    visible: isVerticalLayout
    anchors.left: bottomBar.right
    width: 12
    gradient: Gradient {
        orientation: Gradient.Horizontal
        GradientStop { position: 0.0; color: "#30000000" }
        GradientStop { position: 1.0; color: "transparent" }
    }
}

Initialization Sequence

The Component.onCompleted handler in Main.qml performs a carefully ordered startup sequence:

  1. Capture system font — Store the default font family before any custom fonts are loaded
  2. Load custom themes — Must happen before setTheme() so saved custom themes are available
  3. Apply theme — Set the saved color theme
  4. Load dimensions — Restore window width/height from settings
  5. Initialize Spacing — Update dimension-dependent layout calculations
  6. Set auto-scale — Apply screen detection scale factor
  7. Set UI scale — Apply user preference multiplier
  8. Load environment — Apply the shape/effect preset
  9. Load color transition speed
  10. Connect media manager — Wire up settings manager to media manager
  11. Initialize orientation — Set bottom bar mode
  12. Restore window state — Fullscreen, maximized, or normal
  13. Load shift light flags — For the RPM overlay
  14. Connect RPM signal — Manually connect obdManager.rpmChanged for reliability
Signal Connection Order: The obdManager.rpmChanged signal is connected manually in Component.onCompleted rather than via a Connections block. This is a workaround for better reliability with PySide6 signal handling.
